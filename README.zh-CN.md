# AgentTrail

[English](README.md) | [简体中文](README.zh-CN.md)

在 VS Code 中审查编程智能体的文件变更、记录 Codex 工具活动。
智能体变更和会话时间线均以 Codex hooks 为来源，不调用 AI API。
审查界面跟随 VS Code 显示语言：中文环境显示中文，其他语言统一显示英文。

## 开始使用

1. 打开工作区，扩展会自动捕获审查基线。
2. 按下方步骤接入 Codex，再让 Codex 使用 `apply_patch` 修改文件，在资源管理器中打开 **智能体变更**。
3. 对比并**接受**或**拒绝**单处变更、整个文件或全部待审查变更。接受会保留代码，拒绝会恢复基线。
4. 在 **会话时间线** 查看工具请求、返回结果和工具报告的补丁文件变更；命令元数据可用时显示工作目录、耗时和退出码。

**历史记录**保留已审查的变更供参考。**开始会话**／**重置会话**会开始新一轮审查，旧时间线仍可查看。**结束会话**停止记录，但仍可继续审查已有变更。

安装 Codex 扩展后，可用**请求修改**将选中的变更发送给 Codex，也可通过选区悬浮菜单将代码、文件或文件夹加入对话。

## 接入 Codex

1. 安装 AgentTrail VSIX，打开并信任本地项目。
2. 点击 **会话时间线** 标题栏的插头图标，或执行 **AgentTrail：接入 Codex**。多根工作区需要选择项目，可对其他项目重复接入。
3. 命令会打开用户级 `~/.codex/hooks.json`；如果 VS Code 环境设置了 `CODEX_HOME`，则使用 `$CODEX_HOME/hooks.json`，请确保 VS Code 与 Codex 使用相同的配置目录。原有 hooks 和其他项目的接入配置都会保留；修改已有配置时会在旁边保存备份。每个项目的处理器仅采集该项目内的活动。采集脚本仍安装在 VS Code 的扩展存储目录，不创建或修改项目文件及 Git 忽略规则。
4. 在 Codex 中审查并信任 hooks（CLI 使用 `/hooks`），配置加载后开始新一轮 Codex 任务。仅安装 VSIX 不会自动启用记录。
5. Codex 工作时保持 VS Code 窗口打开。**结束会话**暂停记录；**开始会话**／**重置会话**重新捕获审查基线并恢复记录。

需要 Codex 运行时支持针对 `Bash`、`apply_patch` 的 `PreToolUse`／`PostToolUse`，以及 `SessionEnd`。参考 [Codex hooks 官方文档](https://learn.chatgpt.com/docs/hooks)。扩展不会自动授予 hook 信任。

更新 AgentTrail 或 VS Code 后，再次执行**接入 Codex**以更新采集脚本，并在 Codex 中审查变化的 hook 定义。生成的命令包含本机绝对路径，每台机器需要单独配置。断开某个项目时，只需从用户级 hook 配置中删除标记为 `AgentTrail Codex activity: <项目路径>` 的处理器。

如果之前使用过项目级接入，请重新接入并信任用户级 hooks，然后从 `<项目>/.codex/hooks.json` 中只删除旧的 `AgentTrail Codex activity` 处理器。Codex 会同时加载两处配置，保留旧条目可能导致重复执行或继续调用旧机器路径。扩展不会自动修改旧项目文件；请保留团队其他 hooks。如果文件仅包含 AgentTrail hooks，可以将该文件及其 `.agenttrail-backup-*` 备份从仓库中移除。

## 环境与限制

- 需要 VS Code **1.138+**。时间线无需 Shell Integration 或额外安装 Node.js，采集脚本使用本地 VS Code 可执行文件运行。目前仅支持本地桌面工作区，hooks 与扩展宿主需要位于同一台机器。
- 支持审查已有 UTF-8 文本文件。新增、删除文件仅作为历史记录，二进制文件不在范围内。
- 在 VS Code 中手动编辑会更新该文件的基线；切换 Git 分支会开始新一轮审查。编辑器的撤销操作无法撤销接受变更。
- 两个视图都不将普通文件保存、手动终端命令或其他 Agent 的活动认定为 Codex 变更。文件监听只刷新或失效已有审查项，不产生来源证明。
- `PreToolUse` 显示为请求，不代表已经执行；只记录能与请求配对的结果，接入或重置之前开始的调用不会补录。
- 文件事件要求 `apply_patch` 成功结果明确报告文件路径。Shell 间接生成的文件、无法识别的结果格式不会通过时间窗口推测归属。缺失的退出码、耗时和执行状态显示为未知，失败的补丁不产生成功文件事件。
- **智能体变更**还要求补丁前的内容能精确重建结果，并与操作后的文件一致；无法精确重建的模糊补丁、CRLF 补丁、重命名及混合写入不进入待审查范围。如果文件随后被其他程序修改，待审查项会失效；已确认的 Codex 历史保留。补丁之前已有的非 Codex 修改会纳入基线，不作为 Codex 变更拒绝。
- 命令文本和元数据保留在时间线中，不采集终端输出或提示词。校验补丁需要通过本地临时事件传递文本快照，读取后删除；快照不会作为时间线事件保存。关闭窗口后不继续积累新事件。重载窗口后历史记录和时间线会清空。
- 不修改真实 Git 索引或暂存区。

## 开发

```sh
npm install
npm run compile
npm run test:unit
npm run test:integration
```

按 **F5** 启动扩展开发宿主。集成测试默认使用最新稳定版 VS Code；设置 `VSCODE_EXECUTABLE_PATH` 可测试其他已安装版本。
